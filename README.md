# 项目：期末重点众筹 JTBD完整产品分析
> 项目简介：同校同专业学生众筹上传各自整理的期末复习重点，系统自动合并去重，生成**多人交叉验证版复习重点**。解决独自啃书效率低、往届学长资料过时失效的痛点。

## 一、标准JTBD任务陈述
当**同校同专业的大学生**，在**期末备考划考试重点阶段**，
他们想要**聚合本班/同专业多名同学整理的笔记重点，自动合并去重，产出多人共同校验的期末复习重点文档**，
以便于**减少啃厚教材的时间精力，避开往届学长资料过时、不匹配本届授课考点问题，高效锁定真实考试考点，提升复习效率，获得备考安全感**。

目前替代方案：独自啃教材整理重点、索要/购买学长学姐旧资料、QQ/微信转发零散笔记、人工复制粘贴整合多份笔记。

现有方案痛点：
1. 个人独自整理笔记耗时高，个人视角容易遗漏考试考点；
2. 学长旧资料课程大纲更新，考点与本届课程不匹配，信息过时；
3. 多份笔记分散，手动复制合并、去重工作量巨大，大量重复内容；
4. 无法区分哪些知识点是多人共同标记高频重点，缺少“多人验证”判断依据。

## 二、JTBD结构化分析表
**项目名称**：期末重点众筹
**分析日期**：2026‑10‑15

### 用户画像
- 年龄：18‑22岁本科大学生
- 职业：在校大学生
- 技能水平：可简单编辑、上传文档，无高级文档处理能力；期末时间紧张
- 生活状态：期末多门课程并行备考，时间碎片化；害怕复习抓错重点；不信任网上来路不明复习资料；愿意用自己整理笔记换取他人笔记，厌恶手动整理大量文档。

### 任务分析
- **核心任务**：汇聚同专业多名同学期末笔记，自动合并去重，识别多人共同标记高频考点，生成可信、适配本届课程的复习重点文档。
- **使用情境**：期末考前1‑4周；老师划定考试范围后；同学完成个人笔记整理；不愿独自通读整本教材；怀疑单份笔记存在考点遗漏。
- **现有方案**：①独立阅读教材整理重点；②获取往届学长学姐复习资料；③社交软件互相传递笔记文件，人工整合；④网络网盘搜集公开复习资料。
- **方案痛点**
    1. 个人整理：耗时久，主观筛选容易遗漏考点；
    2. 学长资料：课程迭代更新，考点过时，不适配本届授课；
    3. 手动整合多份笔记：重复内容多，去重合并成本高，无法识别多人共识重点；
    4. 网络搜集资料来源混杂，不能保证适配本校本专业考试。

### 三层次需求
- **功能需求**：支持多人上传课程笔记；笔记自动合并、语义去重；统计、高亮多人共同标记高频知识点；导出可打印复习文档；按学校‑学院‑专业‑课程权限隔离，仅同专业同学参与课程众筹。
- **情感需求**：缓解期末备考焦虑，拥有“多人共同确认，复习方向不会跑偏”安全感；降低复习负担，不用独自啃完整教材；提交自己笔记后获得付出的获得感。
- **社会需求**：搭建同专业同学互助共创学习场景；笔记贡献者获得公开认可；建立集体协作备考氛围，摆脱单打独斗复习模式。

### 验证计划
- 访谈对象：本校大二、大三不同专业学生；有整理笔记习惯、曾经使用过学长复习资料的同学，样本20‑30人。
- 观察方法：观察学生期末阶段笔记交换行为；收集用户对于学长资料失效、手动合并笔记繁琐的真实反馈。
- 测试原型：最小可用原型，支持单课程上传多份文本笔记，实现语义去重、高频知识点高亮；选取班级小范围内测。

## 三、完整解决方案设计
> 当【同校同专业大学生】在【期末备考】情境中，面临【个人划重点容易遗漏考点、学长资料过时、手动整合多份笔记成本高】的挑战时，
> 他们想要【众筹多名同学笔记，自动合并去重生成多人验证版期末重点】，
> 以获得【高效备考的安全感】和【同专业互助共创的社会认可】。
> 目前的解决方案存在【笔记分散、手动合并成本高、无法区分多人共识考点、往届资料和本届课程脱节】的痛点，
> 原因是【缺少面向校内同专业场景笔记聚合工具；语义层面文档合并去重具备技术门槛，人工无法统计知识点被标记频次】。

### 1. 核心功能：解决最关键的功能需求
1. 课程独立空间：按照学校‑专业‑课程建立独立众筹空间，权限隔离，仅本校同专业用户可以上传、查看对应课程笔记；
2. 多格式笔记上传：支持直接粘贴文本，上传 `txt/markdown/docx` 格式笔记；
3. 语义合并 & 智能去重：不做简单字符串比对，采用语义识别，同义不同表述知识点做合并，保留多种表达方式；
4. 高频重点标记：统计同一个知识点出现在多少份上传笔记中；多人共同标记内容高亮置顶，区分「多人验证重点」和「少数人个人补充知识点」；
5. 文档导出：生成整理完毕复习重点，支持 Markdown / PDF 导出，便于打印复习；
6. 防白嫖机制：查看完整众筹重点，用户需要至少上传一份该课程自己整理的笔记。

### 2. 用户体验：满足情感需求的设计要点
1. 轻量化设计：用户直接上传已经写好的现成笔记，不需要在平台内重新编辑撰写；
2. 内容分层展示：文档明确区分【多人共识重点】高亮样式、【个人补充知识点】普通文本，用户一眼识别必复习内容；
3. 正向反馈提示：笔记上传成功提示 `你的笔记已参与合并，当前已有 N 位同学共建这份复习重点`；
4. 克制信息流：去除无关娱乐社交内容，产品聚焦复习备考；
5. 风险免责提示：页面固定提示：> 本重点来源于同学整理，仅作为复习辅助，请结合教材与老师课件使用。规避笔记内容错误带来风险。

### 3. 社交功能：满足社会需求的特色功能
1. 贡献者名单：生成复习文档末尾展示笔记贡献者昵称/匿名列表，体现集体共创；
2. 课程互助看板：展示该课程参与众筹总人数，强化多人共建感知；
3. 笔记质量投票：用户可以对他人上传笔记进行「有用 / 无用」投票；低质量垃圾笔记过滤，不参与合并计算；
4. 班级分享能力：生成重点文档分享链接，可转发班级群，邀请更多同专业同学补充笔记，参与人数越多重点可靠性越高。

### 4. 技术选择：基于约束条件的技术建议
- 前端：优先Web网页，微信浏览器直接打开，无需下载APP；配套微信小程序，降低学生使用门槛；
- 文档解析：成熟docx/txt/markdown解析库，提取上传笔记文本；
- 核心能力（语义去重、知识点聚类）：调用轻量大模型做文本语义相似度比对，聚合同义知识点，统计知识点出现频次；
- 存储：存储原始上传笔记、合并生成后的重点文档；做好隐私管控，原始笔记仅用于合并逻辑，不随意公开；
- 账号权限：学号/校园统一认证，完成学校‑专业权限隔离，阻止外校无关用户干扰课程重点众筹。

## 四、精简版方案（jtbd‑Optimize 模板）
当**同校同专业大学生**在**期末备考整理复习重点**时，
他们想要**汇聚多名同学笔记，自动合并去重得到多人验证的复习重点**，
因为现有方案**个人整理容易遗漏考点、学长资料过时，手动合并多份笔记工作量巨大**。

- **核心功能**：按专业课程隔离空间；多份笔记上传；语义去重合并；统计知识点标记频次，高亮多人共识重点；查看完整内容需要贡献笔记，支持PDF导出。
- **用户体验**：直接上传现成笔记，无需二次编辑；区分共识重点与个人补充；网页&小程序即用即走；增加免责提示规避笔记错误风险。
- **技术方案**：Web网页 + 微信小程序；文档解析库；轻量大模型完成语义相似度聚类；校园学号认证实现课程权限隔离。

## 五、项目风险思考
1. **内容质量风险**：用户上传错误、垃圾笔记；依靠投票过滤机制做基础拦截；产品定位仅作为复习辅助，不能替代教材课件。
2. **版权风险**：只允许上传学生手写整理笔记，禁止上传老师原版课件资料。
3. **冷启动风险**：单门课程参与上传人数过少，“多人验证”价值无法体现；优先从班级获取种子用户，小范围试点。
